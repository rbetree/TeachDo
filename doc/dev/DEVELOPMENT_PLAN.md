## 📋 项目概述

### 参考文档

`doc/dev/FRONTEND_GUIDE.md`

### 核心原则
- ✅ **完整功能保留**: 不可影响或减少任何现有功能
- 🎨 **设计系统统一**: 采用原型中的 Indigo 主题色系和设计规范
- 🔄 **渐进式交付**: 每个任务集合完成后可独立交付价值
- 📱 **响应式优先**: 确保所有页面适配移动端和桌面端
- 🎯 **MVP优先**: 聚焦核心重构目标,避免功能蔓延
- 🔧 **基于现有架构**: 在Vue3+Vite基础上重构,非从零开始

页面原型文件来自历史归档（当前仓库不包含完整原型目录）。下表为历史原型/旧版路由示意，用于对照当时的步骤拆解。

### 后端API对接规范

基于 `doc/legacy/API_*.md`（抓包/历史记录）整理的核心接口:

#### 大纲生成 (doc/legacy/API_OUTLINE.md)
- **POST** `/api/generate/outline`
  - 请求体: `{ topic: string, knowledgebase_ids?: string[] }`
  - 响应: SSE流式返回,最终返回JSON格式大纲数据
  - 使用场景: 主页"主题生成"模式 (V2.2.5)

#### 内容生成 (doc/legacy/API_CONTENT.md)
- **POST** `/api/generate/content`
  - 请求体: `{ outline: OutlineData, template_id: string, knowledgebase_ids?: string[] }`
  - 响应: SSE流式返回,逐页生成幻灯片内容
  - 使用场景: 加载页内容生成 (V5.2.1)

#### 模板管理 (doc/legacy/API_TEMPLATE.md)
- **GET** `/api/templates`
  - 响应: `{ templates: Template[] }`,每个模板包含 `id`, `name`, `image_path`, `intend` 字段
  - 使用场景: 模板选择页 (V4.2.1)

#### 知识库管理 (personaldb服务)
- **POST** `/api/knowledge/upload`
  - 文档上传和向量化存储（代理 personaldb `/upload/`）
  - 使用场景: 主页"文档生成"模式 (V2.2.3)
- **GET** `/api/knowledge/files`
  - 获取当前用户在 personaldb 中已上传文档列表（代理 personaldb `/files/{user_id}`）
  - 使用场景: 知识库文件列表页 / 文件选择器（待实现）
- **DELETE** `/api/knowledge/files/{file_id}`
  - 删除指定 `file_id` 的向量及元数据（代理 personaldb `delete_file_vectors` 对应HTTP接口，待补充）
  - 使用场景: 知识库文档管理与清理（待实现）
- **POST** `/api/knowledge/generate_from_id`
  - 请求体: `{ file_id: string, language: string }`
  - （已取消）原计划基于已向量化文档直接生成 PPT 内容（对齐 `/tools/aippt_by_id` 语义）。如需恢复该能力，需要重新定义入口与协议。

#### 错误处理规范
- **SSE断连**: 前端需实现重连机制和超时处理 (10秒心跳)
- **Agent超时**: 根据 `AGENTS.md`,单个Agent调用超时应友好提示用户
- **模板不存在**: 后端返回404时,前端应有降级处理(使用默认模板)

#### 数据格式约定
- **Outline格式**: 见 `doc/PPT_Structure.md` 的大纲结构定义
- **Template JSON**: 必须包含 `intend: 4` 字段(见 `AGENTS.md`)
- **Chart处理**: 包含图表的slide会被 `content_client.py:process_chart_part_text()` 拆分为多条
