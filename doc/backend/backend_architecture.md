# 后端架构概述

本项目后端采用微服务架构，由多个独立的、专注特定功能的 Agent 服务组成。这种设计提高了系统的模块化、可扩展性和可维护性。所有服务通过统一的脚本进行管理，并共享一套标准化的环境配置机制。

## 核心服务列表

后端系统主要由以下四个核心微服务构成：

| 服务名称        | 端口号 | 主要职责                               |
| --------------- | ------ | -------------------------------------- |
| `main_api`      | 6800   | **API 网关**: 作为系统的统一入口，接收前端请求，并协调其他 Agent 完成任务。 |
| `personaldb`    | 9100   | **知识库服务**: 负责文档（如PDF）的处理、转换、分块和向量化，为内容生成提供知识支持。 |
| `simpleOutline` | 10001  | **大纲生成 Agent**: 基于用户输入和知识库内容，生成演示文稿（PPT）的大纲结构。 |
| `slide_agent`   | 10011  | **内容生成 Agent**: 根据生成的大纲，填充每一页幻灯片的具体内容。 |

## 服务依赖与调用流程

服务之间存在明确的依赖关系，并遵循特定的启动和调用顺序。

### 启动顺序

为了保证系统正常运行，服务必须按照以下依赖链顺序启动：
`personaldb` → `simpleOutline` → `slide_agent` → `main_api`

### 调用流程

典型的调用流程如下：
1.  前端应用将请求发送到 `main_api` (端口 `6800`)。
2.  `main_api` 作为总协调器，通过其内部的客户端包装器 (`outline_client.py`, `content_client.py`)，以 A2A (Agent-to-Agent) 的方式调用其他服务。
3.  `main_api` 首先可能会调用 `personaldb` 来处理和查询相关知识。
4.  接着，`main_api` 调用 `simpleOutline` Agent 来生成内容大纲。
5.  最后，`main_api` 调用 `slide_agent` Agent，基于大纲生成最终的幻灯片内容。
6.  所有 Agent 间的通信使用支持流式响应的 SSE (Server-Sent Events)。

## 统一管理机制

### 启动方式

- **一键启动**: 在项目根目录下执行 `python start.py`，会以“干净模式”输出启动进度与就绪状态（不刷屏）。如需聚合查看所有服务实时日志，请另开终端执行 `python start.py --tail`。
- **单独启动**: 也可使用 `python backend/start_backend.py` 单独启动整个后端服务栈。

### 环境变量加载

- **统一加载**：所有服务都采用同一套 `.env` 合并策略（且**不覆盖**系统环境变量）。
- **优先级（从高到低）**：
  1. 系统环境变量
  2. 服务目录 `.env`（可选，用于本机临时覆盖）
  3. 项目根目录 `.env`（推荐统一维护）
- **关于 `env_template`**：它是模板文件（便于首次复制为 `.env`）；运行时不会被自动读取。`start.py` / `backend/start_backend.py` 可能会在缺少 `.env` 时拷贝该模板。

更详细的变量清单与建议见：`../dev/ENV_GUIDE.md`。
